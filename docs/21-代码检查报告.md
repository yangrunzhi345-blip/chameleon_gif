## 四、确认的 BUG(已修复)

### BUG-1(高)`CacheStorageController.clear()` 语义偏差 → 失败测试 + CI 时段性挂红

- **现象**:`flutter test` 稳定失败一例 ——
  `test/app/application/cache_storage_controller_test.dart`「手动清空 副本全清(含被引用)+ 非 running 工作目录 + 缩略图」,
  `expect(Directory(paths.work).existsSync(), isFalse)` 实际为 `true`。
- **根因**:类注释与文档约定 `clear()` 是「workdir(非 running)**全清**」,但实现复用了启动清理的
  `_cleanupWorkDirs(runningIds, cutoff: _now())`,多了一个 `mtime < cutoff` 的超期条件。
  测试注入的假时钟固定为 `DateTime(2026, 8, 7, 12)`,而工作目录的 mtime 是**真实创建时间**:
  - 测试在**当地 12:00 之后**运行 → mtime > cutoff → 目录被豁免 → 测试失败;
  - 测试在 12:00 之前运行 → 碰巧通过。
  因此这是一个**时段性 flaky 测试**;CI(ubuntu-latest,UTC)同样取决于作业触发时刻,
  与 README「`flutter test` 全绿为提交门槛」直接冲突。
- **修复**(`lib/app/application/cache_storage_controller.dart`):
  `_cleanupWorkDirs` 增加 `requireExpired` 参数(默认 `true`,启动清理行为不变);
  `clear()` 传 `requireExpired: false`,手动清空回归「非活跃目录无条件全清」的文档语义。
- **验证**:修复后该测试在任何时刻都确定性通过,全套件 877 绿。

### BUG-2(中,Windows)`_cleanupWorkDirs` 硬编码 `/` 切分路径 → 任务 id 解析失败

- **位置**:与 BUG-1 同一行,`f.path.split('/').last.substring(9)`。
- **后果**:Windows 临时目录用 `\` 分隔,`split('/')` 不切分,`int.tryParse` 恒为 `null`
  → 所有 `gifforge_<id>` 目录被当作「无主目录」:
  - 启动清理路径有 7 天 TTL 兜底,影响小;
  - **手动清空路径 `cutoff = now`,running/queued 任务的活跃工作目录在 Windows 上会被一并删除**
    (活跃豁免集 `runningIds` 形同虚设),可能破坏进行中的转换。
- **对照**:`TaskManager._cleanupOldWorkDirs` 已正确使用 `split(RegExp(r'[\\/]'))`,此处为漏网。
- **修复**:改为 `split(RegExp(r'[\\/]'))`,与 TaskManager 同惯用法。

### BUG-3(中)采集运行器 stderr 严格 UTF-8 解码 → 未处理流错误

- **位置**:`lib/shared/platform/capture_process_runner.dart`。
- **根因**:stderr 管道用 `utf8.decoder`(严格模式)。项目自己在转码侧已有实证注释
  (`ProcessEngine._drain`:非 UTF-8 文件名(如 GBK)会让 ffmpeg 输出畸形字节,严格解码抛
  `FormatException`),但采集侧(拍摄/录屏)漏了同等防护。采集会话的 stderr 订阅无 `onError`,
  畸形字节会成为**未处理的异步流错误**(拍摄/录屏错误映射依赖 stderr 尾部,恰是文件名出现在
  错误行里的场景)。
- **修复**:改为 `Utf8Decoder(allowMalformed: true)`,与转码引擎同策。

## 六、代码质量亮点(审查确认)

1. **取消竞态治理完备**:`TaskManager` 对「取消 vs 启动」窗口的三重检查
   (`_cancelRequests` 同步登记、byId 后检查、token 登记后复查、完成收尾前复查)覆盖了
   启动、退避重试、收尾三个阶段,注释与实现一致。
2. **进程生命周期无孤儿**:`ProcessEngine` 双流并发消费防管道死锁,异常兜底 `kill`;
   `terminateProcess` kill → 3s 轮询 → SIGKILL 完整时序;采集会话 watchdog 防挂死。
3. **资源泄漏防护**:节流流回收源订阅、播放器双路径幂等 dispose、工作目录上限回收、
   缓存三分区 TTL 清理 + 缩略图 LRU(双层缓存均限量)。
4. **容错降级一致**:历史入库失败不阻塞任务完成、缩略图失败降级图标、相册保存失败不阻塞
   completed、启动清理异常仅日志不阻塞首帧、Isar 损坏行跳过不整表失败。
5. **测试可测性好**:引擎/执行器/时钟/进程启动全部构造注入,fake 夹具齐全;
   命令构造、进度解析、错误分类均为纯函数 + 快照/单测锁定。
