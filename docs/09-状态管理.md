# 09 状态管理

## 9.1 为什么使用 Riverpod

| 需求 | Riverpod 的支撑 |
|------|-----------------|
| 编译期安全 | 未定义/未监听的 Provider 在开发期即报错,重构零意外 |
| 依赖注入 | ProviderScope overrides 可整体替换实现(Mock 测试) |
| 异步状态机 | `AsyncValue` 的 loading/error/data 三态覆盖转码全生命周期 |
| 生命周期管理 | `autoDispose` 会话态自动释放(播放器、表单) |
| 可测试 | 纯函数化 provider + overrides,无全局单例污染 |
| 生态契合 | 与 Freezed/Isar 生成代码无缝协作 |

**替代方案排除理由**见 [03-技术选型](03-技术选型.md) §3.2 Riverpod 行(Bloc 样板多 / GetX 侵入与可测试性差 / Provider 旧版已弃)。

## 9.2 Provider 拆分(三层次)

### 层次一:全局 Provider(应用生命周期,`ProviderScope` 根注入)

| Provider | 类型 | 职责 |
|----------|------|------|
| `isarProvider` | Provider<Isar> | 数据库单例 |
| `taskRepositoryProvider` / `historyRepositoryProvider` / `settingsRepositoryProvider` | Provider<接口> | 仓储注入(实现可换) |
| `ffmpegEngineProvider` | Provider<FFmpegEngine> | 转码引擎(PlatformAdapter 组装) |
| `appLoggerProvider` | Provider<AppLogger> | 日志单例 |
| `themeControllerProvider` | NotifierProvider<ThemeMode> | 主题三态(持久化) |
| `localeControllerProvider` | NotifierProvider<Locale?> | 语言三态(持久化) |
| `taskQueueControllerProvider` | NotifierProvider<TaskQueueState> | 任务队列(常驻,非 autoDispose) |
| `historyControllerProvider` | NotifierProvider<AsyncValue<List<ExportHistory>>> | 历史列表 |

### 层次二:功能 Provider(会话生命周期,`autoDispose`)

| Provider | 模块 | 类型 |
|----------|------|------|
| `importControllerProvider` | Import | NotifierProvider.autoDispose<VideoInfo?> |
| `previewControllerProvider` | Preview | NotifierProvider.autoDispose<PreviewState>(内持 PlayerController) |
| `timelineControllerProvider` | Timeline | NotifierProvider.autoDispose<RangeSelection> |
| `exportControllerProvider` | Export | NotifierProvider.autoDispose<ExportFormState> |
| `presetControllerProvider` | Settings | NotifierProvider.autoDispose<PresetList> |

### 层次三:派生/数据流 Provider

| Provider | 说明 |
|----------|------|
| `activeTaskProvider` | `ref.watch(taskQueueControllerProvider)` 派生的当前任务视图 |
| `exportProgressProvider` | StreamProvider,包装 TaskQueue 进度流 → `AsyncValue<TaskProgress>` |
| `videoInfoFromFileProvider` | FutureProvider,文件→VideoInfo(解析异步) |

## 9.3 状态类型约定

- **异步数据一律 `AsyncValue`**:导入解析、历史列表、视频元数据
- **交互状态用 Notifier**:表单、时间轴选区、主题
- **流式状态用 StreamProvider/订阅**:播放位置、转码进度(节流 200ms 刷新 UI)

## 9.4 持久化边界(什么持久化 / 什么不能)

| 类别 | 是否持久化 | 载体 | 理由 |
|------|-----------|------|------|
| AppSetting(主题/语言/目录/默认参数) | ✅ | SharedPreferences | 跨会话用户偏好 |
| ExportTask(含进度/状态) | ✅ | Isar | 崩溃恢复、队列恢复 |
| ExportHistory | ✅ | Isar | 永久记录 |
| ExportPreset | ✅ | Isar | 用户资产 |
| 播放位置/当前帧 | ❌ | 内存 | 会话态,重开即新 |
| 表单未提交输入 | ❌ | 内存 | 提交即快照 |
| 预览/转码临时文件列表 | ❌(除 taskId 引用) | 内存+临时目录 | 由 CancellationManager 管理 |
| 认证/隐私数据 | ❌ | — | 应用无此需求,数据本地化 |

## 9.6 状态管理与两层分离

- **Controller/Notifier 属于功能层**:位于 `features/<模块>/application/`,是纯 Dart(不依赖 Widget 上下文),由 UI 层经 `ref.watch/read` 消费。
- **Widget 只读状态、不产状态**:页面内禁止直接操作 Isar/SharedPreferences/FFmpeg;一切状态变更经 application 层控制器/用例。
- **UI 瞬态不进 Controller**:动画状态、滚动位置等渲染细节留在 Widget 层(StatefulWidget/ValueNotifier),不污染功能层。
- 收益:功能层 Controller 可在无 Widget 环境下直接单测(`ProviderContainer` 即可,无需 `testWidgets`)。

## 9.7 使用规范(评审强制)

1. `ref.watch` 只用于 build 阶段;事件回调内一律 `ref.read`
2. 会话态(播放器/表单)必须 `autoDispose`,防内存泄漏
3. 全局常驻(队列/仓储)不 autoDispose,明确注释"应用生命周期"
4. 禁止在 Widget 中 `context.read` 修改状态后再重建(用 `ref`)
5. 异步动作:Notifier 内 `state = AsyncLoading` → 成功/失败赋值;禁止裸 `async` 回调
6. Provider 文件命名:`*_controller.dart`(Notifier)、`*_providers.dart`(数据流)
7. 测试:`ProviderContainer` + `overrides`,见 [14-测试计划](14-测试计划.md)
