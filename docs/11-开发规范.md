## 11.1 Git 工作流

### 分支模型

```
main(稳定,可发布)
 └── feat/<模块>-<简述>   # 功能开发(如 feat/task-queue-state-machine)
 └── fix/<简述>           # 缺陷修复
 └── refactor/<简述>      # 重构
 └── docs/<简述>          # 文档
 └── chore/<简述>         # 构建/依赖/杂务
```

- main 为唯一长期分支;禁止直接向 main 提交功能(本机开发可单分支直提,团队协作时启用 PR)
- **任务开始前**:`git status` 确认干净 → `git pull` → 拉功能分支
- **任务完成后**:格式化 → 分析 → 测试 → 提交 → 合并回 main → push

### 提交信息规范

```
<type>(<scope>): <中文描述>

# type: feat | fix | refactor | docs | chore | test | perf | style
# scope: import | preview | timeline | export | history | settings |
#         task-queue | converter | storage | app | deps
# 示例:
#   feat(converter): 支持两遍调色板转换
#   fix(task-queue): 崩溃恢复时重复入队问题
#   chore(deps): 升级 riverpod 至 3.3.1
```

- 一个提交一个逻辑变更;拒绝大杂烩提交
- 提交信息末尾由工具追加 `Co-Authored-By`(AI 协作署名)

## 11.2 Dart 编码规范

| 项 | 规则 |
|----|------|
| 格式化 | `dart format`(行宽 80);提交前必须执行 |
| 静态分析 | `flutter analyze` 零告警;`riverpod_lint` 开启 |
| 命名 | 文件 `snake_case`;类/枚举 `PascalCase`;变量 `camelCase`;常量 `kCamel`;私有 `_` |
| 注释 | 公开 API 必须有 Dartdoc;复杂逻辑写"为什么"而非"是什么" |
| 生成代码 | `.g.dart` / `.freezed.dart` / `*.isar.dart` 禁止手改,整体随生成器版本提交 |
| import 顺序 | dart → flutter → 第三方 → 项目内部(每组空行分隔) |
| 错误 | 禁止空 catch;禁止 `print` 调试输出(用 logger) |

## 11.3 异常处理规范

### 异常层级

```
Exception
 ├── DomainException(业务)
 │    ├── ConversionException(转换流程)
 │    ├── FilePickException(文件选择/解析)
 │    └── SettingsException(配置)
 └── InfrastructureException(基础)
      ├── FFmpegMissingException
      ├── DiskFullException
      └── StorageException
```

- **领域异常**:可预期业务失败,携带 `userMessage`(中文提示)与 `errorCode`
- **基础设施异常**:技术失败,由用例捕获转换后上抛领域语义
- **未知异常**:顶层 catch → 日志(带堆栈)→ 通用错误提示,不崩溃

### 用户提示规范

| 场景 | 提示方式 |
|------|----------|
| 表单校验(起止时间等) | 参数旁内联错误,不弹窗 |
| 转换失败 | 弹窗:错误码 + 用户可操作建议(重试/清理空间/换文件) |
| 后台任务完成/失败 | 系统通知 + 应用内 SnackBar |
| 磁盘/权限错误 | 引导操作(打开设置等) |

## 11.4 日志系统设计

### 级别与通道

| 级别 | 用途 | 输出 |
|------|------|------|
| `debug` | 开发期细粒度(命令、解析原始行) | console 仅 debug 构建 |
| `info` | 生命周期事件(导入/开始/完成) | console + 文件 |
| `warning` | 可恢复异常(重试、降级) | console + 文件 |
| `error` | 失败(带堆栈) | console + 文件 + crash 转储 |
| `fatal` | 不可恢复(启动失败) | 文件 + 崩溃收集 |

### 日志文件布局

```
<appData>/logs/
├── app.log              # 应用主日志(轮转)
├── export-<taskId>.log  # 每次转换独立日志(FFmpeg stderr 全文)
└── crash-<timestamp>.log # 崩溃转储(FlutterError/PlatformDispatcher)
```

### 清理策略

- `app.log`:按大小轮转(10MB),保留 3 份
- `export-*.log`:保留 7 天;历史任务删除时同步清理
- `crash-*.log`:保留 30 天
- 统一由启动时 `LogCleanupService` 执行(后台 isolate)

### 实现:AppLogger

```dart
class AppLogger {
  final Logger console;   // logger 包
  final FileLogger file;  // 自定义输出(写文件+轮转)
  void d(String msg, {Object? error, StackTrace? st});
  void i/w/e/...          // 同构
}
// 使用:final logger = ref.read(appLoggerProvider);
```

**导出专用**:每次转换创建 `ExportLogger`(包装 AppLogger,关联 taskId),FFmpeg stderr 逐行进 export-<taskId>.log,便于问题回溯(与 [08-FFmpeg设计](08-FFmpeg设计.md) LogParser 联动)。

## 11.6 代码评审清单(提交前自查)

- [ ] `dart format` + `flutter analyze` 零告警
- [ ] `flutter test` 全绿,新增逻辑有对应测试
- [ ] 无 `print`、无空 catch、无 TODO 遗留(有则标注 issue)
- [ ] 目录红线遵守(见 [05-目录结构](05-目录结构.md) §5.3)
- [ ] 文案中文、错误可操作
- [ ] 日志覆盖关键路径
- [ ] 文档(如涉版本/接口)已同步
