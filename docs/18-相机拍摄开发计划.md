# 18 相机拍摄开发计划(拍摄视频 → GIF)

> 需求来源:2026-08-06 功能构想(调用设备相机直接拍摄,再制作 GIF;设置界面调整相机参数)。
> 关联文档:[12-开发计划](12-开发计划.md) · [08-FFmpeg设计](08-FFmpeg设计.md) · [04-系统架构](04-系统架构.md) · [07-数据库设计](07-数据库设计.md) · [15-发布计划](15-发布计划.md)
> **状态:规划阶段(需求决策已确认,Android 先行)**。

## 一、目标与非目标

### 目标

1. 调用设备相机**拍摄一段短视频**,拍摄完成后**直接保存到系统相册(相机)**,再从相册调用该视频,**复用 MP4 导入的全部现有代码**进入"视频 → GIF"工作流。
2. 设置页新增"相机"分组:Android **全参数调整**(白平衡/曝光/对焦等,**不含分辨率**);其他设备按各自能力裁剪。
3. 历史记录中的拍摄素材**可重转**(素材文件持久存在,不依赖临时目录)。
4. 按设备分别规划,分阶段落地:**先做 Android**,再跟进 Windows / Linux。

### 非目标(明确不做)

- ❌ 连拍照片合成 GIF(帧率不可控;定格动画另行评估)
- ❌ 录制中实时滤镜/特效
- ❌ 在线相机服务、云处理
- ❌ 麦克风收音(GIF 无声,仅录画面,免录音权限)

## 二、需求决策记录(2026-08-06 评审)

| # | 待决策项 | 决策 | 说明 |

## 三、Android 拍摄闭环(核心流程)

```
相机拍摄(不设分辨率,相机默认) → 存相册(MediaStore.Video,复用/扩展 AndroidMediaStoreSaver)
  → 从相册取视频路径/URI → ffprobe 解析(ParseVideoPort) → /preview 工作台
  → 时间轴裁剪/参数 → TaskManager → 两遍调色板 → GIF → 存相册(现有链路)
```

要点:

- **拍摄**:camera/camerax 插件,取相机能力最优分辨率录像;拍摄时长上限(建议 30s,超时自动停)。
- **存相册**:复用现有 `AndroidMediaStoreSaver` 的 MediaStore 写入模式,新增视频分支(ContentValues 走 `MediaStore.Video`);保存结果(路径/URI)随任务流转,与现有 `GallerySaveResult` 同构。
- **调用视频**:拍摄完成 → 自动导入(或设置页可选"拍完确认")→ 经 `ParseVideoPort` 解析 → `context.push('/preview', extra: VideoInfo)`;与"导入 MP4"的唯一区别是文件来源,下游零改动。
- **全参数设置**:设置页"相机"分组提供白平衡、曝光补偿/锁定、ISO、对焦、变焦、闪光灯等(camera 插件能力内),**不含分辨率**(用户决策 D3);参数持久化走 SharedPreferences。
- **历史重转**:素材在相册持久存在,历史记录引用相册文件路径/URI,重转自然可用(D1)。

## 四、其他设备适配方案(自行设计,D2/D5)

### 4.1 采集与控制分离

桌面端 ffmpeg 只负责采集,控制参数走独立通道:

| 能力 | Android(先行) | Windows | Linux |
|------|---------------|---------|-------|
| 采集 | camera/camerax 插件 | `ffmpeg -f dshow` | `ffmpeg -f v4l2` |
| 实时预览 | ✅ 插件取景框 | ❌ 盲拍(回放兜底) | ❌ 盲拍(回放兜底) |
| 控制参数 | ✅ 全参数(不含分辨率) | ⚠️ COM(`IAMVideoProcAmp`/`IAMCameraControl`,小型 C++ 插件) | ⚠️ `v4l2-ctl` 进程封装 |
| 设备枚举 | ✅ 插件 API | ⚠️ COM/注册表 | ✅ 扫描 `/dev/video*` |
| 分辨率参数 | ❌ 不设(相机默认) | ✅ 可设 | ✅ 可设 |

### 4.2 参数能力分档(与硬件能力对齐)

| 档位 | 范围 | 覆盖 |
|------|------|------|
| 第一档 | 帧率 / 时长上限 / 桌面分辨率 | 三平台 |
| 第二档 | 亮度/对比度/饱和度/白平衡/曝光(UVC 常见控制) | Android + Windows + Linux |
| 第三档 | 变焦/对焦/快门等高级控制 | Android;桌面按设备能力动态显示 |

"全参数"的正确语义 = **设备支持什么,设置页就显示什么**:Linux `v4l2-ctl -l` 枚举,Windows COM 能力标志位,Android 插件能力查询;设置页动态渲染参数行。

### 4.3 统一抽象(符合现有架构)

```
CameraPort(拍摄 / 设备枚举 / 参数控制)
├── Android 实现: camera 插件(全参数控制,分辨率交硬件)
├── Windows 实现: ffmpeg dshow 采集 + COM 控制插件
└── Linux 实现:   ffmpeg v4l2 采集 + v4l2-ctl 封装
```

注入方式与现有 `FfprobeExecutor`/`FFmpegEngine` 一致(PlatformAdapter 选型,业务层零平台分支);新模块 `features/camera`:application(纯 Dart,拍摄会话/参数状态)→ infrastructure(平台实现)→ presentation(拍摄页);拍摄页与设置页相机分组属 app 层组合。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 桌面无实时取景框 | 体验缺口 | 盲拍 + 工作台回放兜底;里程碑 4 截帧预览 |
| 桌面参数受硬件限制 | 全参数承诺落空 | 能力探测 + 动态参数面板,"设备支持什么显示什么" |
| Android 存相册失败(存储/权限) | 流程中断 | 复用现有 `GallerySaveResult` 三态(failed 提示不阻塞);拍摄文件先落应用目录再转存相册 |
| 相册素材被用户删除 | 历史重转失败 | 重转时文件不存在 → 明确提示(仿 `SourceMissingException` 模式) |
| Linux 依赖 v4l-utils | 环境依赖 | deb 声明依赖;缺失时提示安装指引 |
| Windows C++ 插件 | 构建链复杂度 | 插件保持最小面(仅参数控制),采集仍走 ffmpeg |
| camera 与 ffmpeg 同进程内存 | Android 大分辨率压力 | 拍摄即存相册即释放;录制分辨率交相机硬件(不设分辨率) |
| CI 无摄像头 | 自动化覆盖不足 | fake 拍摄器注入;真机走手工清单(与 P8 模式一致) |
