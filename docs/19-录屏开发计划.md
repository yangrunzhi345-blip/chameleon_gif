# 19 录屏开发计划(录屏 → GIF)

> 需求来源:2026-08-06 功能构想(录屏制作 GIF,与相机拍摄同构,复用导入 MP4 的相关代码)。
> 关联文档:[18-相机拍摄开发计划](18-相机拍摄开发计划.md) · [12-开发计划](12-开发计划.md) · [08-FFmpeg设计](08-FFmpeg设计.md) · [04-系统架构](04-系统架构.md)
> **状态:规划阶段(未开工);本文为详细开发计划,含接口草案与工作包任务清单(实施时以代码为准)。与 18 号共用"采集产物 → MP4 → 复用导入链路"架构模式。**

## 一、目标与非目标

### 目标

1. 录制屏幕画面(全屏 / 窗口 / 自定义区域),产物为 MP4,**复用 MP4 导入的全部现有代码**进入"视频 → GIF"工作流。
2. 与拍摄(18 号)流程对齐:Android 录制产物**直接存相册**,再经相册调用视频;设置页新增"录屏"分组(帧率/区域/光标等)。
3. 历史记录中的录屏素材**可重转**(素材持久保存)。
4. 按设备分别规划分阶段落地;**录屏桌面端实现成本低于 Android**(ffmpeg 内置输入),设备顺序详见 §六。

### 非目标(明确不做)

- ❌ 系统音频/麦克风收音(GIF 无声;如需配音另行评估)
- ❌ 摄像头画中画(摄像头拍摄与录屏合并,后续版本)
- ❌ 在线录屏服务、云处理

## 二、核心设计(与拍摄同构)

### 2.1 录制产物 = MP4,全链路复用

```
录屏 → 产物 MP4 → 存相册(Android)/落盘 capturesDir(桌面)
  → 取路径 → ffprobe 解析(ParseVideoPort) → /preview 工作台
  → 时间轴裁剪/参数 → TaskManager → 两遍调色板 → GIF
```

与 18 号完全同一模式:新增部分仅为"录制产出 MP4",下游(解析/预览/时间轴/导出/队列/历史)零改动。

### 2.2 平台方案(桌面端同样走系统 ffmpeg)

| 平台 | 采集方案 | 区域选择 | 备注 |
|------|----------|----------|------|
| Android | MediaProjection(系统录屏 API,经插件或原生封装) | 全屏(可配虚拟显示比例) | 每次录制需用户授权(Android 14 起每次);产物转存相册(MediaStore.Video) |
| Windows | `ffmpeg -f gdigrab` | ✅ 全屏 `-i desktop` / 窗口 `-i title=<名>` / 区域 `-offset_x -offset_y -video_size` | 系统 ffmpeg 原生输入,零新依赖;默认带光标 |
| Linux | `ffmpeg -f x11grab`(X11)/ `-f pipewire`(Wayland,ffmpeg 6.1+) | ✅ `-video_size` + `-i <DISPLAY>+x+y`(X11) | X11 成熟;Wayland 依赖 pipewire + portal 授权;光标 `-draw_mouse` |

### 2.3 统一抽象(符合现有架构)

```
ScreenRecorderPort(录制 / 目标枚举 / 参数控制)
├── Android 实现: MediaProjection 封装(授权 → 录制 → 存相册)
├── Windows 实现: ffmpeg gdigrab 进程调用
└── Linux 实现:   ffmpeg x11grab / pipewire 进程调用
```

注入方式与 `FfprobeExecutor`/`FFmpegEngine` 一致(PlatformAdapter 选型,业务层零平台分支);新模块 `features/screen_record`:application(纯 Dart,录制会话/参数状态)→ infrastructure(平台实现)→ presentation(录制页);录制页与设置页"录屏"分组属 app 层组合。

### 2.4 与 18 号共性的设计(直接复用)

- **产物生命周期**:Android 存相册(`MediaStore.Video`,复用 `AndroidMediaStoreSaver` 视频分支);桌面落盘 `capturesDir`(应用文档目录,决策同 D1/D6)。
- **自动导入**:录制完成 → 自动进入 `/preview` 工作台(录屏无需取景框:用户本就在看屏幕,录完回放兜底)。
- **能力探测 + 动态参数**:设置页"录屏"分组按平台渲染:
  - 三平台:帧率(建议 5–30)、时长上限(建议 60s,超时自动停)
  - Windows/Linux:区域(全屏/窗口/自定义,自定义弹框填 offset/size)、光标开关
  - Android:分辨率比例(全屏/16:9 虚拟显示)、帧率
- 参数持久化走 SharedPreferences(key `record_params`)。

## 三、数据模型与接口草案

> 实施时以代码为准;与 18 号共用 `CaptureResult`/素材目录/存相册模式。

### 3.1 录屏参数模型 `RecordParams`(domain/value_objects/record_params.dart)

```dart
@freezed
class RecordParams {
  /// 帧率(5–30,默认 15)
  double fps;

  /// 时长上限(毫秒,默认 60s,超时自动停)
  int maxDurationMs;

  /// 区域模式:全屏 / 窗口 / 自定义区域
  RecordRegion regionMode;   // fullscreen / window / custom

  /// 窗口模式:目标窗口标题(Windows gdigrab title=)
  String? windowTitle;

  /// 自定义区域:起点 + 尺寸(gdigrab offset/video_size;x11grab DISPLAY+x+y)
  Offset? regionOrigin;
  Size? regionSize;

  /// 是否显示光标(gdigrab 默认带;x11grab 需 -draw_mouse)
  bool drawCursor;

  /// Android 虚拟显示比例(0 = 全屏原生)
  double? aspectRatio;

  /// 素材目录(桌面;null = 默认 capturesDir)
  String? outputDir;
}
```

### 3.2 录屏端口 `ScreenRecorderPort`(domain/repository_interfaces/screen_recorder_port.dart)

```dart
abstract interface class ScreenRecorderPort {
  /// 目标枚举:显示器列表(Windows 多屏/桌面会话)与可抓窗口(Windows)
  Future<List<RecordTarget>> enumerateTargets();

  /// 环境探测(X11/Wayland 判定、pipewire 可用性、gdigrab 可用性)
  Future<RecordCapabilities> queryCapabilities();

  /// 录制:产物落位(Android 转存相册),返回最终路径/URI(同 CaptureResult)
  Future<CaptureResult> record({
    required RecordParams params,
    CancelToken? cancelToken,
  });
}
```

### 3.3 命令装配纯函数(桌面端核心,可快照单测)

`features/screen_record/application/record_command_builder.dart`(仿 `GifCommandBuilder`):

```
输入 RecordParams + 平台 → 输出 ffmpeg 命令列表(Process 执行):
- Windows: [-f, gdigrab, -framerate, F, (-offset_x/-offset_y/-video_size 区域), (-i title=窗口), -t, 上限, out.mp4]
- Linux X11: [-f, x11grab, -framerate, F, -video_size, WxH, (-draw_mouse), -i, DISPLAY(+x+y), -t, 上限, out.mp4]
- Linux Wayland: [-f, pipewire, -i, auto, -t, 上限, out.mp4](环境探测分支)
- 统一尾链: -pix_fmt yuv420p(屏幕 RGB → H.264 兼容像素格式)
```

## 六、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Android 14+ 每次录制需授权 | 流程中断 | 授权引导页 + 取消静默返回录制页;说明授权用途 |
| Wayland 录屏兼容性(pipewire 依赖环境) | Linux 部分环境不可用 | 环境探测(X11 优先);不支持时明确提示 + 指引切换 X11 会话 |
| 窗口抓取依赖窗口标题/前台窗口枚举 | Windows 窗口模式不稳定 | 全屏兜底;窗口枚举失败回退全屏并提示 |
| 录屏产物体积/时长失控 | 磁盘压力 | 时长上限(60s)+ 低帧率默认;产物落盘即释放录制缓冲 |
| 相册素材被删(Android) | 历史重转失败 | 重转提示(同 18 号 SourceMissing 模式) |
| 录屏与拍摄功能重复度高 | 维护成本 | 共用产物/导入衔接骨架(features 抽象共享),差异仅在采集端 |
| gdigrab/x11grab 抓屏内容敏感 | 隐私顾虑 | 录制前确认提示(录制范围提示文案) |

## 七、待决策项(开工前评审)

1. **设备顺序**:Android 先行(与拍摄一致)vs 桌面先行(实现成本更低,`gdigrab`/`x11grab` 零新依赖)——建议 Android 先行保持节奏,桌面端可并行小里程碑
2. 录屏与拍摄是否共用模块骨架(`features/capture` 合并采集抽象)还是独立两模块(当前建议独立,共享衔接层)
3. 默认录制参数:帧率 15、时长上限 60s、全屏模式是否合理
4. 是否需要窗口枚举 UI(Windows)进 MVP
5. 录制产物清晰度策略:桌面按屏幕原生分辨率 vs 固定上限
