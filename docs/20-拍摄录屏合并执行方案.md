# 20 拍摄+录屏合并执行方案

> 前置:需求决策已确认(见 [18-相机拍摄开发计划](18-相机拍摄开发计划.md) §二、[19-录屏开发计划](19-录屏开发计划.md) §二)。
> **执行状态:✅ 已按本方案落地(2026-08-06 ~ 08-07):阶段 A 共享地基(android_media_store saveVideo/capturesDir/CaptureResult/capture_import_use_case/fake 端口)、桌面采集执行(capture_process_runner 统一进程执行 + 两线命令装配纯函数)均已实现;Wayland 分支实施中由 pipewire 改 wf-recorder。**
> 本文为**拍摄(18)与录屏(19)合并执行部分的执行方案**,与两篇开发计划同步维护;
> 合并的是"共享地基",平台采集端按技术分线各自实现。

## 一、合并决策

两个功能按"**共享面合并、平台特有面分线**"执行,理由:

1. **共享骨架面大(约一半代码同一份)**:
   - 产物衔接层完全同构:存相册视频分支(`AndroidMediaStoreSaver`)、素材目录(`capturesDir`)、自动导入 `/preview`、结果模型 `CaptureResult`
   - 历史重转适配一份代码两处受益(素材被删提示,仿 `SourceMissingException`)
   - 测试设施同构:fake 端口模式、"采集 → 导入 → 导出"集成测试、真机手工清单模式
   - 桌面采集骨架同构:拍摄(dshow/v4l2)与录屏(gdigrab/x11grab)**全是 ffmpeg 输入**,命令装配纯函数、Process 执行、yuv420p 尾链同一套;Windows 窗口枚举 C++ 插件与拍摄 COM 控制插件可合并为一个插件
2. **平台特有技术差异大,不能整包合并**:Android 两条线(CameraX 拍摄 vs MediaProjection 录屏)授权流程、编码路径、插件选型完全独立,混做时问题归因困难;单次迭代范围过大,一条线出问题会阻塞另一条线验收。
3. **单开发者 + AI 协作场景**:一次规划、共享地基一次落地、Android 真机一次手工清单验证两条链路,减少上下文切换(与 [17-P7P8-合并执行方案](17-P7P8-合并执行方案.md) 同理由)。

**不变项**:提交粒度不变(共享层/拍摄/录屏各自独立提交);阶段门按链路分别验收,失败不互相阻塞;手工清单放最终代码上执行。

## 二、共享面盘点(合并开发的内容)

| 共享资产 | 位置(目标) | 归属 |
|----------|------------|------|
| 存相册视频分支(`MediaStore.Video`) | `shared/platform/android_media_store.dart` 扩展 `saveVideo()` | 阶段 A |
| 素材目录 `capturesDir` + 命名规范 | `PlatformAdapter` 新增 getter(仿 `systemTempDir`);`capture_<ts>_<seq>.mp4` | 阶段 A |
| 结果模型 `CaptureResult`(路径/时长/三态) | `domain/value_objects/capture_result.dart` | 阶段 A |
| 自动导入衔接(素材路径 → `ParseVideoPort` → `/preview`) | `app/application/` 公共用例(拍摄/录屏共用) | 阶段 A |
| 历史重转素材被删提示 | `features/history/application/history_controller.dart` | 阶段 A |
| fake 端口测试设施 | `test/fixtures/fake_camera_port.dart`、`fake_screen_recorder_port.dart`(同构) | 阶段 A |
| 桌面命令装配纯函数骨架 | `record_command_builder.dart` 与 `ffmpeg_camera_port.dart` 共享装配模式(快照测试) | 阶段 C |
| Windows C++ 插件(窗口枚举 + COM 参数控制) | `windows/` 平台工程,单插件两个通道 | 阶段 C |

## 三、合并执行结构(三个阶段)

### 阶段 A:采集基础设施(共享地基,一次落地)

| WP | 内容 | 涉及文件(代表) | 顺序 |
|----|------|----------------|------|
| A-WP1 | 存相册视频分支 + `capturesDir` + `CaptureResult` | `android_media_store.dart`(saveVideo)、`platform_adapter.dart`(capturesDir)、`domain/value_objects/capture_result.dart` | 1 |
| A-WP2 | 自动导入公共用例 + 历史重转提示 | `app/application/capture_import_use_case.dart`(素材 → 解析 → push `/preview`)、`history_controller.dart`(素材不存在提示) | 2 |
| A-WP3 | 测试设施:fake 端口 ×2 + 集成测试骨架 | `test/fixtures/fake_camera_port.dart`、`fake_screen_recorder_port.dart`、`integration_test/capture_flow_test.dart`(以 fake 驱动"采集→导入→导出") | 3 |

**阶段门**:存相册视频分支单测通过;自动导入用例可独立单测;fake 端口驱动集成测试跑通;
`flutter analyze` 零告警、`flutter test` 全绿;`feat(capture): 采集基础设施(共享层)`

### 阶段 B:Android 两闭环(分线并行,共享阶段 A)

| WP | 内容 | 说明 |
|----|------|------|
| B-C1 | 拍摄闭环(18 号 C1-WP2..WP5) | CameraX:授权 → 拍摄 → 存相册 → 自动导入;设置页相机分组(全参数) |
| B-S1 | 录屏闭环(19 号 S1-WP2..WP5) | MediaProjection:授权 → 录制 → 存相册 → 自动导入;设置页录屏分组 |

- 两线先后或并行执行(共享层已就绪,互不阻塞);阶段门分开验收(拍摄门 / 录屏门)。
- 共享:路由加两条(`/capture`、`/record`)、首页入口两个(见 18/19 号 UI 入口章节)、真机手工清单一次执行验证两链路。

**阶段门(分别)**:Android 真机拍摄/录屏 → 存相册 → 自动导入 → 裁剪 → 导出全链路通过;
`feat(camera): Android 相机拍摄闭环` / `feat(screen-record): Android 录屏闭环`

### 阶段 C:桌面采集(合并做,共享阶段 A + ffmpeg 骨架)

| WP | 内容 | 涉及文件(代表) | 顺序 |
|----|------|----------------|------|
| C-WP1 | 命令装配纯函数(拍摄 + 录屏共用模式) | `record_command_builder.dart`(gdigrab/x11grab/pipewire 分支)、`ffmpeg_camera_port.dart`(dshow/v4l2 分支);快照测试全覆盖 | 1 |
| C-WP2 | Windows 设备/窗口枚举 + COM 控制插件 | `windows/` C++ 插件(单插件两通道:枚举 + 参数控制) | 2 |
| C-WP3 | Linux 采集(v4l2 采集 + v4l2-ctl 参数;x11grab/pipewire 录屏) | `features/` infrastructure 复用骨架 | 3 |
| C-WP4 | 设置页按能力裁剪 + 首页入口平台态 | `settings_screen.dart`、`home_page.dart`(置灰 + tooltip 策略,见 18/19 号 UI 入口章节) | 4 |
| C-WP5 | 测试 + 手工清单(Windows/Linux) | 命令快照、枚举单测(fake)、真机清单 | 5 |

**阶段门**:Windows 真机拍摄+录屏全链路(第二档参数/三区域模式);Linux X11 拍摄+录屏全链路;
Wayland 探测与提示正确;`feat(capture-desktop): 桌面采集(拍摄+录屏)`

## 四、里程碑节奏

```
W1  阶段 A(共享地基)                     ← 一次规划、一次落地
W2  阶段 B-C1(拍摄闭环)+ B-S1 起步
W3  阶段 B-S1(录屏闭环)+ Android 手工清单   ← Android 双功能可演示
W4  阶段 C-WP1..WP2(命令骨架 + Windows 插件)
W5  阶段 C-WP3..WP5(桌面采集 + 手工清单)   ← 全平台
W6  (可选)体验增强(18/19 号里程碑 4)
```

## 五、风险与对策(合并执行特有)

| 风险 | 影响 | 对策 |
|------|------|------|
| 共享层设计分歧拖累两线 | 阶段 A 阻塞 B/C | 阶段 A 接口最小化(端口 + 结果模型 + 衔接用例),争议点后置 |
| 两线并行时真机环境冲突(同一台 Android 设备) | 测试排队 | 拍摄/录屏真机验证可先后执行,不要求并行 |
| Windows C++ 插件两通道耦合 | 单通道故障影响另一功能 | 插件内通道独立(枚举通道 + 参数通道),各自错误处理 |
| 桌面命令骨架抽象过度 | 拍摄/录屏命令差异被强行统一 | 命令装配按"输入设备类型"分支(摄像头/屏幕),不追求单函数全兼容 |
