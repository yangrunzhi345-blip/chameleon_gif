# 18 相机拍摄开发计划(拍摄视频 → GIF)

> 需求来源:2026-08-06 功能构想(调用设备相机直接拍摄,再制作 GIF;设置界面调整相机参数)。
> 关联文档:[12-开发计划](12-开发计划.md) · [08-FFmpeg设计](08-FFmpeg设计.md) · [04-系统架构](04-系统架构.md) · [07-数据库设计](07-数据库设计.md)
> **状态:规划阶段(未开工)**。本文为可行性结论与实施计划的正式化,开工前需评审确认范围与档位。

## 一、目标与非目标

### 目标

1. 调用设备相机**拍摄一段短视频**,自动进入现有"视频 → GIF"工作流,导出 GIF。
2. **复用 MP4 导入的全部现有代码**:拍摄产物 = 临时 MP4 文件,走 `ParseVideoPort` → `/preview` 工作台(时间轴裁剪/参数/导出),下游零改动。
3. 设置页新增"相机"分组,调整相机参数(分辨率/帧率等,按平台能力裁剪)。
4. 拍摄完成后的衔接支持两种模式:**自动导入**(直接进工作台)与**拍摄预览**(先回放确认,满意再进工作台)。

### 非目标(明确不做)

- ❌ 连拍照片合成 GIF(帧率不可控,曝光不一致;定格动画需求另行评估)
- ❌ 录制中实时滤镜/特效
- ❌ 在线相机服务、云处理
- ❌ 麦克风收音(GIF 无声,仅录画面,免录音权限)

## 二、核心设计决策

### 2.1 拍摄产物 = 临时 MP4,全链路复用

```
相机拍摄(录像) → 临时 MP4 → ffprobe 解析(ParseVideoPort) → /preview 工作台
              → 时间轴裁剪/参数 → TaskManager → 两遍调色板 → GIF
```

现有链路只认"MP4 文件路径",不关心来源。新增部分仅为"录像产出临时文件"一步,
下游(解析/预览/时间轴/导出/队列/历史)全部复用,零侵入。

### 2.2 采集与控制分离(桌面端关键)

桌面端 ffmpeg 只负责采集画面,**控制参数走独立通道**:

| 能力 | Android | Windows | Linux |
|------|---------|---------|-------|
| 采集 | camera/camerax 插件 | `ffmpeg -f dshow` | `ffmpeg -f v4l2` |
| 实时预览 | ✅ 插件自带取景框 | ❌ 盲拍(回放兜底) | ❌ 盲拍(回放兜底) |
| 控制参数 | ✅ 插件全参数 | ⚠️ COM 接口(需 C++ 插件) | ⚠️ `v4l2-ctl` / ioctl |
| 设备枚举 | ✅ 插件 API | ⚠️ COM/注册表 | ✅ 扫描 `/dev/video*` |

**参数能力分档**(与硬件能力对齐,见 §2.4):

| 档位 | 范围 | 覆盖平台 |
|------|------|----------|
| 第一档 | 分辨率 / 帧率 / 时长上限 | Android + Windows + Linux |
| 第二档 | 亮度/对比度/饱和度/白平衡/曝光(UVC 常见控制) | Android + Windows(COM)+ Linux(v4l2-ctl) |
| 第三档 | 变焦/对焦/快门等高级控制 | Android;桌面按设备能力动态显示 |

### 2.3 统一抽象(符合现有架构)

```
CameraPort(拍摄 / 设备枚举 / 参数控制)
├── Android 实现: camera 插件(全参数 + 实时预览)
├── Windows 实现: ffmpeg dshow 采集 + COM 控制插件
└── Linux 实现:   ffmpeg v4l2 采集 + v4l2-ctl/ioctl 控制
```

- 注入方式与现有 `FfprobeExecutor`/`FFmpegEngine` 一致(PlatformAdapter 选型,业务层零平台分支)
- 新模块 `features/camera`:application(纯 Dart,拍摄会话/参数状态)→ infrastructure(平台实现)→ presentation(拍摄页)
- 拍摄页与设置页属 app 层组合(跨模块 UI 收敛)

### 2.4 能力探测与动态参数面板

"全参数"的正确语义 = **设备支持什么,设置页就显示什么**:

- Android:camera 插件提供能力查询(分辨率列表/控制项支持)
- Linux:`v4l2-ctl -l` 枚举控制项(或 ioctl `VIDIOC_QUERYCTRL`)
- Windows:COM `IAMVideoProcAmp`/`IAMCameraControl` 接口能力标志位
- 设置页"相机"分组按探测结果动态渲染参数行;参数持久化走 SharedPreferences(与现有默认参数同套路)

## 三、数据流与复用点(最小改动面)

| 环节 | 复用 | 新增 |
|------|------|------|
| 拍摄 | — | `features/camera` 模块(端口 + 三平台实现 + 拍摄页) |
| 拍完衔接 | `/preview` 路由(extra 传 VideoInfo) | 拍摄页"使用/重拍"按钮 |
| 解析 | `ParseVideoPort`(ffprobe) | — |
| 工作台 | `preview_screen` + 时间轴 + 参数面板 | — |
| 导出 | ExportController → TaskManager → 命令构造 | — |
| 设置页 | SharedPreferences 默认参数模式 | "相机"分组(按能力动态) |

## 六、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 桌面无实时取景框 | 体验缺口 | 盲拍 + 工作台回放兜底;里程碑 4 截帧预览 |
| 桌面参数受硬件限制 | 全参数承诺落空 | 能力探测 + 动态参数面板,"设备支持什么显示什么" |
| Linux 依赖 v4l-utils 安装 | 环境依赖 | deb 声明依赖;缺失时提示安装指引 |
| Windows C++ 插件 | 构建链复杂度 | 插件保持最小面(仅参数控制),采集仍走 ffmpeg |
| camera 插件与 ffmpeg 同进程内存 | Android 大分辨率压力 | 拍摄分辨率上限提示;临时文件即拍即释放 |
| 临时素材文件生命周期 | 历史重转素材丢失 | 拍摄产物落"拍摄素材"目录(非系统临时目录);历史重转对已删素材提示 |
| CI 无摄像头 | 自动化覆盖不足 | fake 拍摄器注入;真机走手工清单(与 P8 模式一致) |

## 七、待决策项(开工前评审)

1. 拍摄素材落盘位置:应用文档目录 `camera/`(历史可重转)vs 系统临时目录(轻量但历史重转受限)
2. 桌面端参数控制通道:Linux `v4l2-ctl` 进程调用(轻)vs ioctl 直调(重、干净);Windows 是否引入 C++ 插件
3. 拍摄时长上限与分辨率默认值(建议 30s / 720p)
4. 是否需要"拍摄预览确认"作为 MVP 的一部分(见里程碑 4)
5. 档位确认:是否首版只做里程碑 1(Android),桌面端随版本跟进
