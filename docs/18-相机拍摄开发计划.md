# 18 相机拍摄开发计划(拍摄视频 → GIF)

> 需求来源:2026-08-06 功能构想(调用设备相机直接拍摄,再制作 GIF;设置界面调整相机参数)。

## 一、目标与非目标

### 目标

1. 调用设备相机**拍摄一段短视频**,拍摄完成后**直接保存到系统相册(相机)**,再从相册调用该视频,**复用 MP4 导入的全部现有代码**进入"视频 → GIF"工作流。
2. 设置页新增"相机"分组:Android **全参数调整**(白平衡/曝光/对焦等,**不含分辨率**);其他设备按各自能力裁剪。
3. 历史记录中的拍摄素材**可重转**(素材文件持久存在,不依赖临时目录)。
4. 按设备分别规划,分阶段落地:**先做 Android**,再跟进 Windows / Linux。

### 非目标(明确不做)

- ❌ 连拍照片合成 GIF(帧率不可控;定格动画另行评估)
- ❌ 录制中实时滤镜/特效
- ❌ 在线相机服务、云处理
- ❌ 麦克风收音(GIF 无声,仅录画面,免录音权限)

## 三、Android 拍摄闭环(核心流程)

```
相机拍摄(不设分辨率,相机默认)→ 私有目录临时文件 → 存相册(MediaStore.Video)
  → 删除私有副本 → 取相册路径/URI → ffprobe 解析(ParseVideoPort) → /preview 工作台
  → 时间轴裁剪/参数 → TaskManager → 两遍调色板 → GIF → 存相册(现有链路)
```

要点:

- **拍摄**:camera/camerax 插件,取相机能力最优分辨率录像;拍摄时长上限(默认 30s,超时自动停)。
- **存相册**:复用现有 `AndroidMediaStoreSaver` 的 MediaStore 写入模式,新增视频分支(ContentValues 走 `MediaStore.Video`);保存结果(路径/URI)随任务流转,与现有 `GallerySaveResult` 同构。
- **调用视频**:拍摄完成 → 自动导入 → 经 `ParseVideoPort` 解析 → `context.push('/preview', extra: VideoInfo)`;与"导入 MP4"的唯一区别是文件来源,下游零改动。
- **全参数设置**:设置页"相机"分组提供白平衡、曝光补偿/锁定、ISO、对焦、变焦、闪光灯等(camera 插件能力内),**不含分辨率**(D3);参数持久化走 SharedPreferences。
- **历史重转**:素材在相册持久存在,历史记录引用相册文件路径/URI,重转自然可用(D1)。

## 四、其他设备适配方案(D2/D5)

### 4.1 采集与控制分离

桌面端 ffmpeg 只负责采集,控制参数走独立通道:

| 能力 | Android(先行) | Windows | Linux |
|------|---------------|---------|-------|
| 采集 | camera/camerax 插件 | `ffmpeg -f dshow` | `ffmpeg -f v4l2` |
| 实时预览 | ✅ 插件取景框 | ❌ 盲拍(回放兜底) | ❌ 盲拍(回放兜底) |
| 控制参数 | ✅ 全参数(不含分辨率) | ⚠️ COM(`IAMVideoProcAmp`/`IAMCameraControl`,小型 C++ 插件) | ⚠️ `v4l2-ctl` 进程封装 |
| 设备枚举 | ✅ 插件 API | ⚠️ COM/注册表 | ✅ 扫描 `/dev/video*` |
| 分辨率参数 | ❌ 不设(相机默认) | ✅ 可设 | ✅ 可设 |

### 4.2 参数能力分档(与硬件能力对齐)

| 档位 | 范围 | 覆盖 |
|------|------|------|
| 第一档 | 帧率 / 时长上限 / 桌面分辨率 | 三平台 |
| 第二档 | 亮度/对比度/饱和度/白平衡/曝光(UVC 常见控制) | Android + Windows + Linux |
| 第三档 | 变焦/对焦/快门等高级控制 | Android;桌面按设备能力动态显示 |

"全参数"的正确语义 = **设备支持什么,设置页就显示什么**:Linux `v4l2-ctl -l` 枚举,Windows COM 能力标志位,Android 插件能力查询;设置页动态渲染参数行。

## 六、数据模型与接口草案

> 实施时以代码为准;新增模型一律带默认值,序列化遵循项目约定(freezed / json_serializable)。

### 5.1 拍摄参数模型 `CaptureParams`(domain/value_objects/capture_params.dart)

```dart
@freezed
class CaptureParams {
  /// 帧率(1–60,默认 15;桌面端含分辨率,Android 忽略分辨率字段)
  double fps;
  int? resolutionWidth;      // 桌面端使用;Android 不设(D3)
  int? resolutionHeight;

  /// 时长上限(毫秒,默认 30s,超时自动停)
  int maxDurationMs;

  /// 相机控制参数(能力探测后动态渲染;仅 Android 全参数)
  int? whiteBalanceTemp;     // 白平衡色温(K)
  bool whiteBalanceAuto;
  double? exposureCompensation;
  bool exposureLock;
  int? iso;
  FocusMode focusMode;       // auto/continuous/manual
  double? zoom;              // 变焦倍数
  bool flashOn;

  /// 素材目录(桌面;null = 默认 capturesDir)
  String? outputDir;
}
```

### 5.2 拍摄端口 `CameraPort`(domain/repository_interfaces/camera_port.dart)

```dart
abstract interface class CameraPort {
  /// 设备枚举(桌面返回可用摄像头列表;Android 返回前后摄)
  Future<List<CameraDevice>> enumerateDevices();

  /// 能力探测(控制项/分辨率/帧率支持范围;设置页动态渲染依据)
  Future<CameraCapabilities> queryCapabilities(String deviceId);

  /// 设置参数(设置页改动即时生效;Android 插件级,桌面 v4l2-ctl/COM)
  Future<void> applyParams(CaptureParams params);

  /// 拍摄:录像到素材文件并落位(Android 转存相册),返回最终路径/URI
  Future<CaptureResult> capture({
    required CaptureParams params,
    CancelToken? cancelToken,
  });
}

/// 拍摄结果:finalPath = 相册路径/URI(Android)或素材文件路径(桌面);
/// galleryStatus 三态复用 GallerySaveResult(保存失败不阻塞拍摄完成)
class CaptureResult {
  final String finalPath;    // 供导入链路/历史记录引用
  final int durationMs;      // 实际录制时长
  final GallerySaveStatus galleryStatus;
  final String? galleryUri;
}
```

### 5.3 素材目录与命名

- `PlatformAdapter` 新增 `capturesDir` getter(仿 `systemTempDir`):
  - Android:返回相册写入语义路径(实际经 MediaStore)
  - 桌面:返回 `~/Documents/chameleon_gif/captures/`,首次使用 `createSync(recursive: true)`
- 命名:`capture_<yyyyMMdd_HHmmss>_<seq>.mp4`(时间戳 + 序号防重名)
- 桌面设置页"素材存储位置"可选自定义(默认即用,持久化 SharedPreferences,key `capture_dir`)

## 九、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 桌面无实时取景框 | 体验缺口 | 盲拍 + 工作台回放兜底;里程碑 4 截帧预览 |
| 桌面参数受硬件限制 | 全参数承诺落空 | 能力探测 + 动态参数面板,"设备支持什么显示什么" |
| Android 存相册失败(存储/权限) | 流程中断 | `GallerySaveResult` 三态(failed 提示不阻塞);私有副本保留供手动处理 |
| 相册素材被用户删除 | 历史重转失败 | 重转时文件不存在 → 明确提示(仿 `SourceMissingException` 模式) |
| Linux 依赖 v4l-utils | 环境依赖 | deb 声明依赖;缺失时提示安装指引 |
| Windows C++ 插件 | 构建链复杂度 | 插件保持最小面(仅参数控制),采集仍走 ffmpeg |
| camera 与 ffmpeg 同进程内存 | Android 大分辨率压力 | 拍摄即存相册即释放;录制分辨率交相机硬件(不设分辨率) |
| CI 无摄像头 | 自动化覆盖不足 | fake 拍摄器注入;真机走手工清单(与 P8 模式一致) |
