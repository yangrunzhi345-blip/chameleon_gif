# 🦎 Chameleon Gif

一个把视频和图片做成 GIF 的桌面小工具,支持 Linux / Windows / Android。

## 这是干什么的?

简单说,就是你手上有段视频、或者几张图片,想弄成一个 GIF。发群里当表情包、给教程配个动图、把游戏片段转出来分享 —— 反正就是这类需求。

那为什么不直接用在线工具?因为视频得先传上去,文件大一点就慢,而且谁知道服务器拿你的视频干嘛。为什么不直接敲 ffmpeg?你记得住 `palettegen` 后面那一长串参数吗?反正我记不住,每次都要翻文档。所以我就想,干脆自己做一个小应用:本地转码不传文件,可视化操作不用记参数,转完还能排队、能存历史、能一键重转。Chameleon Gif 就是这么来的。

它的定位就是一个"自己用着顺手、别人用着也顺手"的小工具,不搞云服务、不搞账号体系,打开就能转。

对了,为什么叫 Chameleon?变色龙,颜色多嘛,跟 GIF 这玩意儿挺配的。图标就是一只小变色龙。

为什么选 Flutter 来做?因为我想一套代码同时覆盖 Linux、Windows、Android 三个平台,不用写三遍。桌面和手机上都能用,参数、历史这些行为三端一致。开发下来最省心的部分,其实是"界面和逻辑彻底分开"这件事 —— 界面上加个按钮,逻辑一点不用动;逻辑改个参数规则,界面也跟着变。这个后面技术架构那节会细说。

## 它能干什么?

**视频转 GIF**

选一个 MP4,应用里会实时预览。在时间轴上拖出起止区间(精确到毫秒),调一下帧率、尺寸、循环次数,点转换。转换过程有实时进度条,做完了可以直接打开所在文件夹,也可以另存到别处。

画质方面用的是"两遍调色板法":先扫一遍全片,生成一个全局调色板,再照着这个调色板输出 GIF。比单遍转换多花一点时间,但颜色过渡平滑得多,高动态画面(比如游戏片段、烟花、渐变背景)差距一眼能看出来。所以默认就是两遍,想要快可以切标准模式。

**多张图片合成 GIF**

把几张 PNG / JPG 按顺序合成为一个帧动画,每张图的停留时长、整体帧率、质量都能调。图片列表支持上移、下移、删除、追加,顺序不对随时改。

这里有个坑是后来才填上的:以前如果两张图尺寸不一样(比如一张 1024×1024 的方图,一张 1080×1920 的竖图),合成的时候第二张会被硬生生拉伸成第一张的大小,看着很别扭。现在不会了 —— 每张图都保持自己的比例,在统一画布内居中,多余的地方用透明填充。不管什么尺寸混排,图都不会变形,透明区域放在暗色背景或者聊天框里都自然。

**每张图还能单独调**

如果想让动画里某一张图更大一点、或者单独指定它的宽度高度,点图片右边的齿轮图标,会进一个专门的控制页:等比缩放倍数、宽度、高度,三个参数互不影响。改的时候旁边有实时预览,画布比例和最终效果都能看到,点"保存"才生效,想反悔可以"恢复默认"。没动过的图完全不受影响。回到列表页,齿轮旁边会显示这张图改过的参数(比如"缩放倍率:2 宽度:480"),哪些图动过一眼就知道。这些参数还会跟着转换任务一起存进历史,以后重转能原样复现。

**队列、历史这些基本功都有**

一次想转好几段视频?批量导入,排队转,两个任务同时跑。历史记录存在本地数据库里,详情、重转、删除、清空都有。程序中途崩了也不慌 —— 重启后没转完的任务会自动重新排队,转出来的东西不会丢。

## 一些你可能关心的小事

**转出来的文件在哪?** 默认存在系统的临时目录里,转完弹窗里点"另存为"自己选地方;也可以在转换前就指定导出目录,它会记住,下次默认还是那里。Android 上直接帮你存进相册,方便分享。

**转一半想反悔?** 随时可以取消,正在转的会立刻停,临时文件也会清理干净,不会在磁盘上留一堆垃圾。

**会不会很吃资源?** 转码是在独立的进程/库里跑的,界面不会卡。一个几分钟的视频转 GIF 一般十几秒到一分钟,取决于分辨率和帧率。500MB 的大视频也能流畅操作。

**图片尺寸乱七八糟?** 上面说了,统一画布 + 透明填充,不拉伸。如果你就是想让某张图变形(比如故意压扁做成搞笑效果),去精细控制页把宽度高度都指定了,它会照做 —— 你说了算。

## 一些设计上的小心思

几个你可能没注意、但确实是刻意为之的地方:

**默认就开高质量。** 两遍调色板确实慢一点,但大多数人转 GIF 要的就是"好看",而不是"最快"。你随时可以切标准模式,选择权在你。

**透明填充而不是白底。** 图片尺寸不一致的时候,很多工具的做法是补白边,在深色背景下一块白特别扎眼。我们选了透明,暗色聊天框、深色网页里都自然。这是当年做表情包被白边坑过之后才定的。

**历史能重转,而且参数原样。** 不只是重转那么简单 —— 每张图片的精细控制参数、当时的帧率尺寸循环,全都跟着历史记录存下来了。几个月后看到一条历史想再转一次,点一下,出来跟当时一模一样。这个做起来比听起来麻烦,因为要保证"崩溃了、重启了、参数还在"。

**界面和逻辑分开,不是为了炫技。** 好处很实际:改界面不会碰坏逻辑,修逻辑不用动界面,测试也跑得快。图片模式从"大家一起拉伸"改成"每张图独立控制",逻辑层改完,界面层几乎没动,全靠当初这个分层。

## 怎么上手?

1. 打开应用,点「导入 MP4」选视频,或者点「图片制作 GIF」选图片
2. 视频:在时间轴上选好起止区间;图片:排好顺序
3. 调帧率、尺寸这些参数,点「开始转换」
4. 进度条走完,弹窗里打开文件夹、另存为,完事

小提示:动态画面多的内容建议开「高质量」(调色板两遍);简单的录屏用标准模式,转得快。

## 从源码构建

环境要求:Flutter SDK >= 3.38、Dart >= 3.10,桌面端运行还需要系统 ffmpeg。

```bash
git clone <仓库地址> && cd chameleon_gif

flutter pub get                                                       # 拉依赖
dart run build_runner build --delete-conflicting-outputs              # 生成 freezed/isar/riverpod 代码
flutter run -d linux                                                  # 桌面运行(Linux;按平台换 -d)
```

开发常用的命令:

```bash
dart format .                            # 格式化
flutter analyze                          # 静态分析(要求零告警)
flutter test                             # 单元测试(要求全绿)
dart run tool/probe_check.dart           # ffprobe 链路自检
dart run tool/convert_check.dart         # 真实转码 SHA-256 一致性验证
```

## 技术架构

代码按"组合根 → 功能模块 → 领域层 → 基础设施"四层组织,依赖方向单向:app 只做组装,功能模块内部再分"纯 Dart 功能层 + UI 层",domain 不依赖任何 Flutter 的东西。直接收益是:核心逻辑能脱离界面单独测,UI 里只剩渲染和转发。

技术选型,挑几个关键的说:

- **转码引擎接口抽象**(`FFmpegEngine`):桌面调系统 ffmpeg 二进制,Android 用内置 FFmpegKit,业务层不感知平台差异 —— macOS / Web 落地时各补一个实现即可。
- **命令构造是纯函数**(`GifCommandBuilder`):输入参数输出命令列表。图片模式那条链尤其讲究(画布尺寸规则、保持比例、pad 前必须 `format=rgba` 才有真透明、超画布用 min 钳制),全部有快照测试锁着,乱改参数语义测试会报警。
- **状态管理用 Riverpod 3**:会话态 autoDispose 自动清理;进度走节流 Stream 不重建页面;任务调度是独立状态机(双并发槽、失败重试、崩溃恢复),只调度不转码。
- **持久化用 Isar**(本地 NoSQL):任务、历史、每张图的精细控制参数都存里面 —— 崩溃恢复和历史重转能原样复现参数就靠它。
- **错误分类成领域异常**:源缺失、磁盘满、输出冲突各有错误码,UI 只显示中文文案,不泄露路径。

质量方面:`flutter analyze` 零告警是提交门槛;549 个测试全绿(命令构造快照、进度解析、仓储往返、控制器、页面 Widget);三平台同参输出 SHA-256 一致有脚本验证;生成式代码只经 build_runner 产出,不手改。

架构细节、设计取舍、版本锁定表在 `docs/` 目录有 17 篇文档,想深挖的去翻。
