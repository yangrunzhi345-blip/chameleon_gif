## 3.2 选型决策表(为什么选 / 替代方案 / 最终选择)

### Flutter / Dart

| 项 | 内容 |
|----|------|
| 为什么选 | **产品核心特点是全平台**:一套 Dart 代码渲染 Linux/Windows/Android(及预留平台);自绘引擎保证三平台 UI 像素级一致;热重载迭代快;Material 3 开箱即用;桌面端性能接近原生(Impeller/OpenGL)。 |
| 替代方案 | ① **React Native/Electron**:JS 生态,但桌面渲染一致性差、包体大、性能弱;② **Kotlin Multiplatform + Compose Multiplatform**:Android/桌面强,但 Linux 支持弱、学习成本高;③ **Rust + Tauri**:体积最小,但 UI 能力与迭代速度不及 Flutter。 |
| 最终选择 | **Flutter**。理由:全平台一致性是最高优先级;MP4→GIF 是 I/O 密集而非纯计算密集任务,FFmpeg 已负责计算,UI 层性能需求 Flutter 完全满足。 |

### FFmpeg(转码引擎,桌面=系统二进制 + Android=内嵌库)

| 项 | 内容 |
|----|------|
| 为什么选 | GIF 编码是标准化的帧序列化工作,没有理由自研;FFmpeg 的 palettegen/paletteuse 滤镜是当前质量最优的 GIF 编码路径。**桌面(Linux/Windows)经 `dart:io Process` 调系统 ffmpeg/ffprobe 二进制**(Flutter 桌面主流做法);Android 用 `ffmpeg_kit_flutter_minimal`(活跃维护 fork,内置 FFmpeg+FFprobe 原生库,随包分发)。 |
| 实证事实 | `ffmpeg_kit_flutter_minimal` 6.0.8 **无 Linux/Windows 平台实现**(pubspec 无 `flutter: plugin:` 声明,包内仅 android/ios/macos 目录;adapter 源码对非 Android/iOS/macOS 返回不兼容)——桌面真实运行会 MissingPluginException,已实证。P1 已按此修订落地。 |
| 替代方案 | ① **media_kit_ffmpeg**:**经查证该包在 pub.dev 上不存在**(media_kit 生态无 FFmpeg CLI 封装),排除;② **ffmpeg_kit_flutter(原版 6.0.3)**:2025 年起停止维护(2026-07 归档只读),Flutter 3.44 兼容风险,排除;③ **ffmpeg_kit_flutter_new_min(3.6.2)**:活跃但官方声明**不支持 Linux**(首发平台),排除;④ 自研 GIF 编码器:工作量巨大且质量不可比,排除;⑤ 桌面统一系统二进制:三平台转码引擎不一致,但差异已收敛于 PlatformAdapter,Android 内嵌库与桌面二进制均可经同一命令参数构造器驱动(测试复用)。 |
| 最终选择 | 混合方案:**桌面 = 系统 ffmpeg/ffprobe 二进制(Process.run)+ Android = ffmpeg_kit_flutter_minimal ^6.0.8**,差异收敛于 `PlatformAdapter`(lib/shared/platform)。桌面缺二进制时抛 `FFmpegMissingException`,P9 打包决策(预检/携带)见 [12-开发计划](12-开发计划.md) P9 备注。 |
| 风险 | fork 依赖的第三方风险与回退预案见 [13-风险分析](13-风险分析.md) R-07;桌面系统二进制依赖见 R-07 修订。 |

### Riverpod(状态管理)

| 项 | 内容 |
|----|------|
| 为什么选 | 编译期安全的 Provider 体系(未监听即报错);`AsyncValue` 内置 loading/error/data 状态机,天然契合异步转码场景;依赖注入零样板;3.x 统一 `Ref` API,自动重试;与 Freezed/Isar 生态无缝衔接。 |
| 替代方案 | ① **Bloc**:事件驱动严谨但样板代码多(Event/State/Bloc 三件套),开发速度低;② **GetX**:API 简单但侵入性极强、全局单例污染、可测试性差、社区争议大;③ **Provider(旧版)**:已被 Riverpod 取代。 |
| 最终选择 | **Riverpod 3.x + riverpod_generator**(notifier 类代码生成,减少手写模板)。 |

### GoRouter(路由)

| 项 | 内容 |
|----|------|
| 为什么选 | Flutter 官方维护(flutter/packages);声明式路由表集中管理;支持 ShellRoute 实现桌面/移动差异化导航壳;深链与状态恢复能力强。 |
| 替代方案 | ① **Navigator 1.0 命令式**:页面多后路由散落各文件,难维护;② **auto_route**:代码生成强大,但依赖第三方且模板化;③ **routemaster**:社区小。 |
| 最终选择 | **go_router ^17.3.0**。 |

### Freezed + json_serializable(模型)

| 项 | 内容 |
|----|------|
| 为什么选 | 不可变模型 + `copyWith` + 联合类型(如 `TaskState` 各状态不同字段)+ 与 json_serializable 组合一次生成全部样板;V2 阶段大量参数模型需要 copyWith 派生。 |
| 替代方案 | ① 手写不可变类:样板多、易错;② **equatable**:仅解决相等性,copyWith/union/JSON 仍需手写;③ 纯 mutable 类:并发/异步场景易出难查 bug。 |
| 最终选择 | **freezed ^3.2.5 + json_serializable ^6.9.0**(经 build_runner)。 |

### Isar(本地数据库)

| 项 | 内容 |
|----|------|
| 为什么选 | 高性能(底层二进制,比 SQLite 快数倍);类型安全 + 代码生成;**离线原生支持 Linux/Windows/Android**;查询简洁;无原生工程配置负担;与 Freezed 模型可组合(Isar 3.x 支持将对象存为字段)。 |
| 替代方案 | ① **Hive**:性能好但无关系/复杂查询;② **drift/SQLite**:SQL 样板多、类型安全弱于 Isar、桌面打包要带 sqlite3 原生依赖;③ **ObjectBox**:绑定商业授权条款,license 约束多。 |
| 最终选择 | **isar_community ^3.3.2 系列**(社区维护版):官方 `isar 3.1.0` 的生成器依赖旧 source_gen,与现代生成器组合(freezed/riverpod_generator,source_gen ≥4)解析冲突,无法共存;`isar_community` 系列(2026-03 更新)API 兼容(import `package:isar_community/isar.dart`),解决该冲突。该替换正是 [13-风险分析](13-风险分析.md) R-04 预案的落地,仍注意 4.x 未稳定,禁止升级 4.0-dev。 |

### Logger(日志)

| 项 | 内容 |
|----|------|
| 为什么选 | API 极简(`logger.d/i/w/e`)、支持带样式的多级别输出、可自定义输出通道(console/文件/崩溃收集),足够支撑 [11-开发规范](11-开发规范.md) 的日志体系。 |
| 替代方案 | ① 官方 `logging`:功能正确但 API 繁琐,需要自己封装层;② `dart:developer log`:仅面向调试器。 |
| 最终选择 | **logger ^2.5.0**,内部再封装一层 `AppLogger`(统一格式、文件落盘、崩溃转储)。 |

### SharedPreferences(轻量存储)

| 项 | 内容 |
|----|------|
| 为什么选 | 存储"小而频繁读"的偏好(主题、语言、最近目录、默认导出目录)最合适;读快、零配置。 |
| 替代方案 | Isar 存 KV:杀鸡用牛刀;手写配置文件:要自己处理读写/竞态/原子性。 |
| 最终选择 | **shared_preferences ^2.5.0**(仅存偏好,结构化数据一律 Isar,见 [07-数据库设计](07-数据库设计.md) 存储边界)。 |

### MediaKit(视频预览)

| 项 | 内容 |
|----|------|
| 为什么选 | 基于 **libmpv** 的官方级播放器库:桌面三平台渲染成熟、硬解支持好、内置 FFmpeg 原生库;提供 PlayerController 流式事件,适合时间轴联动。(注:转码引擎独立使用 ffmpeg_kit_flutter_minimal,播放与转码为两套原生库,包体略增但换取转码引擎的活跃维护。) |
| 替代方案 | ① 官方 `video_player`:桌面支持很弱(Linux 长期 beta、Windows 通过插件);② `chewie`:只是 video_player 的 UI 封装,无法解决底层;③ 自建 Texture 播放:工作量巨大。 |
| 最终选择 | **media_kit ^1.1.11 + media_kit_video ^1.2.5 + media_kit_libs_video ^1.0.5**。 |

### file_picker + file_selector(文件选择)

| 项 | 内容 |
|----|------|
| 为什么选 | `file_picker` 打开文件(选 MP4)体验统一、支持类型过滤与多选(V2 批量);`file_selector` 是官方 federated 方案,桌面保存对话框(GIF 导出目录)原生可靠。两者各司其职。 |
| 替代方案 | 仅 file_selector:打开对话框定制少、多选体验弱;仅 file_picker:保存对话框在部分平台有已知问题。 |
| 最终选择 | **file_picker ^11.0.2(打开)+ file_selector ^1.0.3(保存)**,统一封装在 `FilePickService`(见 [06-模块设计](06-模块设计.md) Import 模块)。 |

### 开发辅助

| 项 | 内容 |
|----|------|
| build_runner | 唯一生成器运行器,`dart run build_runner build --delete-conflicting-outputs` |
| flutter_lints + riverpod_lint | 官方 lint + Riverpod 专属规则(如 `ref.watch` 使用规范),CI 强制零告警 |

## 3.3 技术栈全景图

```
┌─────────────────────────── Presentation ───────────────────────────┐
│  Flutter (Material 3)   GoRouter   Riverpod(AsyncValue)          │
├─────────────────────────── Application ───────────────────────────┤
│  UseCases   TaskManager   FilePickService(封装 file_picker/file_selector) │
├─────────────────────────── Domain ────────────────────────────────┤
│  Freezed 实体/值对象   Repository 接口  领域异常                   │
├─────────────────────────── Infrastructure ────────────────────────┤
│  Isar(community)仓储   SharedPreferences   Logger   FFmpegService(ffmpeg_kit_minimal) │
├─────────────────────────── Platform ──────────────────────────────┤
│  PlatformAdapter(路径/权限/信号)   media_kit + media_kit_libs_video  │
└────────────────────────────────────────────────────────────────────┘
```

## 3.4 版本变更流程

1. 提出变更(为什么、影响面、回归测试方案)
2. 评审通过后更新本表 + pubspec.yaml(同一次提交,`chore(deps)` 或 `fix(deps)`)
3. `flutter pub get` 更新 lock 文件一并提交
4. 全平台冒烟测试(MVP 后由 CI 执行)
