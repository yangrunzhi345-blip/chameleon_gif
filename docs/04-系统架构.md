# 04 系统架构

> 技术选型:[03-技术选型](03-技术选型.md) · 目录结构:[05-目录结构](05-目录结构.md) · 模块设计:[06-模块设计](06-模块设计.md)

## 4.1 架构总览

采用**分层架构(五层)** + 领域驱动思想,严格单向依赖。核心原则:**依赖方向只向内**;最内层(Domain)零依赖。

```
┌───────────────────────────────────────────────────────────────────┐
│  Presentation(展示层) — lib/app + lib/features/*/presentation      │
│  Widget / 页面 / 路由 / AsyncValue 绑定 / 主题 / 本地化             │
├───────────────────────────────────────────────────────────────────┤
│  Application(应用层) — lib/features/*/application + services       │
│  用例编排 / TaskManager / 导航服务 / 通知服务                       │
├───────────────────────────────────────────────────────────────────┤
│  Domain(领域层) — lib/domain                                      │
│  实体 / 值对象 / 仓储接口 / 领域异常(零依赖,纯 Dart)               │
├───────────────────────────────────────────────────────────────────┤
│  Infrastructure(基础设施层) — lib/shared/repositories + services   │
│  Isar 仓储实现 / SharedPreferences / FFmpegService / Logger        │
├───────────────────────────────────────────────────────────────────┤
│  Platform(平台适配层) — lib/shared/platform                        │
│  PlatformAdapter / 路径解析 / 权限 / 平台差异封装(media_kit 原生)   │
└───────────────────────────────────────────────────────────────────┘
```

**依赖方向:** `Presentation → Application → Domain ← Infrastructure ← Platform`
(Domain 不依赖任何层;Infrastructure/Platform 依赖 Domain 的接口;Platform 是 Infrastructure 的最底层支撑)

## 4.2 各层职责与禁区

### Presentation 展示层

| 项 | 内容 |
|----|------|
| 负责 | 页面与组件渲染;把 `AsyncValue` 状态映射为 UI;用户输入 → 调用 Application 用例;主题/本地化呈现 |
| 不做 | ❌ 业务规则判断 ❌ 直接调用 FFmpeg/Isar/SharedPreferences ❌ 直接构造 FFmpeg 命令 ❌ 自己管理任务状态机 |
| 依赖 | Application(用例)、Domain(只读展示实体) |

### Application 应用层

| 项 | 内容 |
|----|------|
| 负责 | 用例编排:`ImportVideoUseCase`(解析→入库→通知预览)、`ConvertVideoUseCase`(构建任务→入队→完成收尾);`TaskManager` 任务调度;跨模块协调(Import→Preview→Export 的流程控制);导航与通知 |
| 不做 | ❌ 具体技术实现(命令细节、数据库 SQL、平台 API)❌ 写 Widget |
| 依赖 | Domain(接口)、Infrastructure(经由接口注入,不在本层 new) |

### Domain 领域层(最内层)

| 项 | 内容 |
|----|------|
| 负责 | 实体 `VideoInfo/ExportTask/ExportHistory/ExportPreset`;值对象 `GifSetting/TaskState/TaskProgress`;仓储接口 `HistoryRepository/TaskRepository/SettingsRepository`;领域异常 `ConversionException` 等 |
| 不做 | ❌ import 任何 Flutter 库 ❌ 依赖任何第三方包 ❌ 感知 Infrastructure 实现 |
| 依赖 | 无(纯 Dart) |

### Infrastructure 基础设施层

| 项 | 内容 |
|----|------|
| 负责 | 实现 Domain 仓储接口(IsarTaskRepository、IsarHistoryRepository…);`FFmpegService`(基于 ffmpeg_kit_flutter_minimal 的转码执行);SharedPreferences 适配;Logger 落盘 |
| 不做 | ❌ 被 Presentation/Application 反向依赖(只能通过接口)❌ 业务规则 ❌ 决定"什么时候转" |
| 依赖 | Domain(接口)、Platform(Adapter) |

### Platform 平台适配层

| 项 | 内容 |
|----|------|
| 负责 | `PlatformAdapter` 统一封装:FFmpeg 二进制定位(桌面内嵌库 vs Android 内嵌库)、路径规则(Android 沙盒目录 vs 桌面用户目录)、进程信号差异、平台权限(存储权限等) |
| 不做 | ❌ 转码业务逻辑 ❌ 命令构造 |
| 依赖 | 无业务依赖;被 Infrastructure 调用 |

## 4.3 依赖注入方式

- **不用**手写 ServiceLocator。所有跨层依赖经 **Riverpod Provider** 注入(编译期类型安全)。
- 注入清单:

| 接口(Domain) | 实现(Infrastructure) | Provider |
|---------------|----------------------|----------|
| `TaskRepository` | `IsarTaskRepository` | `taskRepositoryProvider` |
| `HistoryRepository` | `IsarHistoryRepository` | `historyRepositoryProvider` |
| `SettingsRepository` | `SharedPrefsSettingsRepository` | `settingsRepositoryProvider` |
| `FFmpegEngine`(Domain 接口) | `FFmpegKitEngine`(基于 ffmpeg_kit_flutter_minimal) | `ffmpegEngineProvider` |
| `FilePickPort`(Domain 接口) | `FilePickService` | `filePickServiceProvider` |

- 测试时用 ProviderScope `overrides` 替换为内存实现(Mock),见 [14-测试计划](14-测试计划.md)。

## 4.5 架构规则(CI 强制)

| 规则 | 校验方式 |
|------|----------|
| domain/ 不得 import `package:flutter` 与第三方包 | `flutter analyze` + import 审查(代码评审) |
| features 之间互不 import | 评审 + 目录边界约定(见 [05-目录结构](05-目录结构.md)) |
| 仓储实现只存在于 shared/repositories | 目录约定 |
| Presentation 不直接引用 ffmpeg_kit_flutter_minimal 类型 | 类型只经 Domain 接口暴露 |

## 4.6 为什么不用其他架构

| 候选 | 不选原因 |
|------|----------|
| 纯 MVC / 简单三层 | 转码、队列、历史、设置的相互依赖很快会让层间混乱,不可维护 |
| Feature-First(全部平铺) | 缺少领域隔离,批量/队列阶段会失控 |
| 事件驱动 CQRS 全量 | 过度设计;项目规模无需命令总线,普通用例编排足够,但保留"未来演进"接口 |
| DDD 仓储全量+UoW | 单机应用、单数据库,UnitOfWork 无收益 |

架构演进方向(V3):若插件系统落地,Application 层用例将抽象为 SPI,见 [16-V2.0扩展规划](16-V2.0扩展规划.md)。
