# 19 录屏开发计划(录屏 → GIF)

> 需求来源:2026-08-06 功能构想(录屏制作 GIF,与相机拍摄同构,复用导入 MP4 的相关代码)。
> 关联文档:[18-相机拍摄开发计划](18-相机拍摄开发计划.md) · [12-开发计划](12-开发计划.md) · [08-FFmpeg设计](08-FFmpeg设计.md) · [04-系统架构](04-系统架构.md)
> **状态:规划阶段(未开工)**。与 18 号文档共用同一套"采集产物 → 临时 MP4 → 复用导入链路"架构模式。

## 一、目标与非目标

### 目标

1. 录制屏幕画面(全屏 / 窗口 / 自定义区域),产物为 MP4,**复用 MP4 导入的全部现有代码**进入"视频 → GIF"工作流。
2. 与拍摄(18 号文档)流程对齐:Android 录制产物**直接存相册**,再经相册调用视频;设置页新增"录屏"分组(帧率/区域/光标等)。
3. 历史记录中的录屏素材**可重转**(素材持久保存)。

### 非目标(明确不做)

- ❌ 系统音频/麦克风收音(GIF 无声;如需配音另行评估)
- ❌ 摄像头画中画(摄像头拍摄与录屏合并,后续版本)
- ❌ 在线录屏服务、云处理

## 二、核心设计(与拍摄同构)

### 2.1 录制产物 = 临时 MP4,全链路复用

```
录屏 → 产物 MP4 → 存相册(Android)/落盘(桌面)→ 取路径 → ffprobe 解析(ParseVideoPort)
  → /preview 工作台 → 时间轴裁剪/参数 → TaskManager → 两遍调色板 → GIF
```

与 18 号文档完全同一模式:新增部分仅为"录制产出 MP4",下游(解析/预览/时间轴/导出/队列/历史)零改动。

### 2.2 平台方案(桌面端同样走系统 ffmpeg)

| 平台 | 采集方案 | 区域选择 | 备注 |
|------|----------|----------|------|
| Android | MediaProjection(系统录屏 API,经插件或原生封装) | 全屏(可配虚拟显示比例) | 每次录制需用户授权(Android 14 起每次授权);产物转存相册(MediaStore.Video) |
| Windows | `ffmpeg -f gdigrab` | ✅ 全屏 `-i desktop` / 窗口 `-i title=<窗口名>` / 区域 `-offset_x -offset_y -video_size` | 系统 ffmpeg 原生输入,零新依赖;默认带光标 |
| Linux | `ffmpeg -f x11grab`(X11)/ `-f pipewire`(Wayland,ffmpeg 6+) | ✅ `-video_size` + `-i <DISPLAY>`(X11) | X11 成熟;Wayland 依赖 pipewire 环境;光标 `-draw_mouse` |

**重要事实:录屏的桌面端实现成本低于 Android** —— `gdigrab` / `x11grab` 是 ffmpeg 内置输入,纯 `Process` 调用即可,与"桌面 = 系统 ffmpeg"架构完全一致;而 Android MediaProjection 需要原生封装。设备顺序规划见 §四。

### 2.3 统一抽象(符合现有架构)

```
ScreenRecorderPort(录制 / 区域枚举 / 参数控制)
├── Android 实现: MediaProjection 封装(授权 → 录制 → 存相册)
├── Windows 实现: ffmpeg gdigrab 进程调用
└── Linux 实现:   ffmpeg x11grab / pipewire 进程调用
```

注入方式与 `FfprobeExecutor`/`FFmpegEngine` 一致(PlatformAdapter 选型,业务层零平台分支);新模块 `features/screen_record`:application(纯 Dart,录制会话/参数状态)→ infrastructure(平台实现)→ presentation(录制页);录制页与设置页"录屏"分组属 app 层组合。

### 2.4 与 18 号文档的共性设计(直接复用)

- **产物生命周期**:Android 存相册(`MediaStore.Video`,复用/扩展 `AndroidMediaStoreSaver` 的视频分支);桌面落盘至应用文档目录 `screen_record/`(可重转,决策同 D1)。
- **自动导入**:录制完成 → 自动进入 `/preview` 工作台;录屏无取景框,靠工作台回放兜底(与桌面拍摄同一策略)。
- **能力探测 + 动态参数**:设置页"录屏"分组按平台渲染:
  - 三平台:帧率(建议 5–30)、时长上限(建议 60s,超时自动停)
  - Windows/Linux:区域(全屏/窗口/自定义,自定义弹框填 offset/size)、光标开关
  - Android:分辨率比例(全屏/16:9 虚拟显示)、帧率
- 参数持久化走 SharedPreferences(与现有默认参数同套路)。

## 三、核心流程(Android 示例,与 18 号 D3 对齐)

```
录制页(开始/停止 + 时长上限)→ MediaProjection 授权 → 录制 → 产物 MP4
  → 存相册(相机)→ 取路径/URI → ParseVideoPort 解析 → 自动导入 /preview
  → 时间轴裁剪 → 导出 GIF → 存相册(现有链路)
```

桌面端流程差异:无授权步骤;产物落应用文档目录;区域选择在录制前配置(全屏/窗口/自定义)。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Android 14+ 每次录制需授权 | 流程中断 | 授权引导页 + 取消静默返回录制页;说明授权用途 |
| Wayland 录屏兼容性(pipewire 依赖环境) | Linux 部分环境不可用 | 环境探测(X11 优先);不支持时明确提示 + 指引切换 X11 会话 |
| 窗口抓取依赖窗口标题/前台窗口枚举 | Windows 窗口模式不稳定 | 全屏兜底;窗口枚举失败回退全屏并提示 |
| 录屏产物体积/时长失控 | 磁盘压力 | 时长上限(60s)+ 低帧率默认;产物落盘即释放录制缓冲 |
| 相册素材被删(Android) | 历史重转失败 | 重转提示(同 18 号 SourceMissing 模式) |
| 录屏与拍摄功能重复度高 | 维护成本 | 共用产物/导入衔接骨架(features 抽象共享),差异仅在采集端 |

## 七、待决策项(开工前评审)

1. **设备顺序**:Android 先行(与拍摄一致)vs 桌面先行(实现成本更低,`gdigrab`/`x11grab` 零新依赖)——建议 Android 先行保持节奏,桌面端可并行小里程碑
2. 录屏与拍摄是否共用模块骨架(`features/capture` 合并采集抽象)还是独立两模块(当前建议独立,共享衔接层)
3. 默认录制参数:帧率 15、时长上限 60s、全屏模式是否合理
4. 是否需要窗口枚举 UI(Windows)进 MVP
5. 录制产物清晰度策略:桌面按屏幕原生分辨率 vs 固定上限
